CREATION AND FAILURE SEMANTICS
Both entry paths first validate strings, canonical root/segments and local-drive type before
Directory.Exists, File.Exists or existing path helpers can probe the filesystem. The existing
policy refusing Network/CDRom/NoRootDirectory/Unknown drive types is preserved. Mapped-drive
ordering is SOURCE-REVIEWED ONLY, not established by the literal UNC fixture. No drive/share
was created, mapped, contacted or experimentally probed.
The parent path is then validated and a create-new, delete-on-close claim serializes ordinary
creators. Existing/nonempty targets and unsafe paths are refused.
A new staging file is opened with RW access and sharing compatible with SQLite's Windows
VFS. Physical identity is checked around SQLite open before issuing schema/configuration
SQL. Schema creation and metadata insertion commit in one transaction in this new file.
After SQLite closes, ReOpenFile obtains DELETE custody on the retained original object.
Publication is a no-replacement handle rename of that object, never a path-based move.
Cancellation is checked before publication. Unpublished normal failures delete only the
created staged object by its retained handle. Unexpected journals or failed cleanup remain
explicit recovery evidence; there is no directory sweep or automatic repair.
Publication is the commit boundary. After it, admission completes without converting a
confirmed creation into a cancellation. A final admission failure reports Published=true
through CortexSemanticBaselineCreationException and must not trigger an automatic retry.
The newly published file is rechecked against its original physical identity and descriptor.

REOPEN AND PRESERVATION SEMANTICS
OpenVerifiedAsync requires an exact path and expected descriptor, never creates a file and
always uses SqliteOpenMode.ReadOnly with pooling disabled.
Read/share-read custody refuses concurrent writes, deletion/replacement and hard links.
Before SQLite open, the 100-byte SQLite header must select rollback-journal read/write
versions, this application ID and this user_version. WAL input and unresolved sidecars are
refused before engine access: ReadOnly SQLite alone would not prove absence of WAL/SHM writes.
Only connection-local query_only/trusted_schema settings are set on verified reopen.
Every schema object is inspected. Only expected exact table DDL and SQLite's automatic
indexes belonging to those tables are admitted; broad LIKE-prefix exclusions are not used.
Stored identity must exactly match the supported schema fingerprint and expected instance.
No old database, raw/sealed/user data, current MCP/pipe or installed binding is a test input.

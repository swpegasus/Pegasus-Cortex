# Cortex 2 resident communication

Resident contract for Cortex `2.2026.10.07.15.19.A`, 2026-10-07. Native and MCP
adapters share the existing signed-in host. This contract adds no service,
network listener or firewall rule. Discovery and signed-package verification
are not proof of a live consumer connection; verify its hello before use.

## Ownership and discovery

The existing signed-in `bin/host/PegasusCortex.Host.exe` owns one semantic
composition and central SQLite store for its Windows owner/session. Two local
wire adapters share it; neither opens a store per connection:

- Native: `pegasus-cortex-native-v1-<actual Windows session>`.
- MCP: `pegasus-cortex-mcp-v1-<actual Windows session>`.

`PegasusCortex.exe connections describe` returns bounded discovery metadata,
not readiness proof. Resolve the installed product root through its registered
location, not a source path. Before sending credentials, validate the actual
named-pipe server's PID-derived executable path against the canonical,
non-reparse `bin/host/PegasusCortex.Host.exe`, and its OS SID/session against
the signed-in caller. The server independently captures the client SID,
session, PID and executable; caller claims cannot supply those identities.
Network and anonymous identities are denied. Applications running as
LocalService/session zero cannot act as the semantic owner.

Cerebral's admitted signed-in `Cerebral.Worker.exe` is the native client.
Its direct Worker route and any service-coordinated connector route must be
identified from the selected caller; ordinary semantic calls do not inherently
require the service relay. Verify the exact canonical executable selected by
the consumer and its existing enrollment before diagnosing authentication.
An identical apphost copied to another path does not inherit that enrollment.
Do not launch a private Cortex MCP instance for the consumer. Model inference
and the selected Worker payload remain Cerebral-owned.

## Registered application credentials

Keys are random 256-bit values, transported as 64 lowercase hex characters.
They supplement OS identity; they do not replace it, establish namespace
permission by name, or authorize System work. The owner registry contains only
salted SHA-256 verifiers of random keys, public key IDs, generations, exact
executable identities, transport, expiration, revocation and routing defaults. It is
bounded to 32 entries/128 KiB in protected current-user configuration.

Explicit owner commands:

```text
PegasusCortex.exe connections register --client cerebral --application <canonical-existing-Worker.exe> --transport native --defaults-file <absolute-json-file>
PegasusCortex.exe connections rotate --client cerebral --application <canonical-existing-Worker.exe> --transport native --defaults-file <absolute-json-file>
PegasusCortex.exe connections list
PegasusCortex.exe connections revoke cerebral
```

Typical Cerebral routing-default file, at most 16 KiB:

```json
{"readNamespaces":["project.pegasus-cerebral","knowledge.shared"],"writeNamespaces":["project.pegasus-cerebral"],"pao":true}
```

These arrays are suggested selections, not permissions. An authenticated local
owner client may explicitly select any shared/project namespace for reads or
writes, including namespaces absent from its defaults. No enrollment/rotation
is needed to change selections. Cortex is a library, not a per-client data
gatekeeper. Only `knowledge.user` (and its legacy `user.preferences` name)
depends on the loaded personal profile. Unload withholds personal results;
core shared/project operations continue. Existing databases are neither
remapped nor generated by registration. Identifier validation, exact record
coordinates, revision concurrency and idempotency still apply.

Enrollment returns only public identity, expiration and credential-file path.
The `<current-user-config>/connections/<clientId>.key` file is Windows
CurrentUser DPAPI (`CRYPTPROTECT_UI_FORBIDDEN`, no optional entropy) over UTF-8
JSON `{clientId,keyId,apiKey}`. Consume it only in the admitted signed-in
application boundary. Do not put keys in command arguments, environment,
agent/model context, records, logs, receipts or packages. The public registry
is `clients.v1.json`; both files inherit the private owner directory ACL.
Enrollment expires after 90 days. Rotation invalidates previous generations;
revocation/expiry is rechecked before each request. A partial enrollment fails
closed; explicit rotation repairs it. Revoked/expired entries never auto-issue.

The managed local Codex adapter has one product-owned registration bound to
the installed semantic executable. Its key is
created once at first resident startup, expires after one year and is never
copied into Codex configuration. Explicit `connections rotate-codex` renews it;
revocation, expiry, missing or corrupt existing credentials are not silently
repaired. External MCP clients may register transport `mcp`, bind the
installed semantic adapter executable and launch
`PegasusCortex.exe stdio --client <registered-client-id>`. Only the public ID is
an argument; the adapter reads the protected local key. Default Codex remains
`PegasusCortex.exe stdio` and uses the same resident runtime.

## Native framing and operations

Native is **not MCP wire**. Frames use the existing binary codec: eight-byte
header (`UInt16LE major=1`, `UInt16LE minor=0`, `Int32LE payloadBytes`) followed
by UTF-8 JSON. Reject incompatible versions and lengths before allocation.
Hello is at most 4,096 bytes; ordinary requests 262,144; responses 524,288.
Unicode is emitted directly; required JSON/control escapes are preserved.

First frame, after OS/server verification:

```json
{"op":"hello","contract":"pegasus.cortex.native/1","clientId":"cerebral","keyId":"<public-id>","apiKey":"<secret-from-protected-file>"}
```

Optional `cwd` preserves an explicit canonical caller context for PAO; it is
not identity/authorization and PAO still performs workspace/path admission. Prefer
explicit `cwd` or `ws` on individual PAO calls. Hello authentication has a
three-second deadline. The response echoes `ok`, `contract`, `product`, actual
`version`, `ownerSid`, `session`, `clientId`, `state=ready`,
`storageKind=sqlite-v2`, size/connection limits and `network=false`.
Validate identity/contract, not identical application release numbers.
Preserve a bounded public refusal code before deserializing a success hello:
`contract_mismatch` and `client_auth_failed` are distinct from a missing frame
or a failed connection. `client_auth_failed` aggregates owner, client activity,
key identity, transport, application path, key shape, and verifier checks; it
does not establish that the API key itself is defective. Never record the
hello credential or weaken identity/size guards to obtain a connection.

An installed method-body inspection can establish which fields that binary
constructs; it does not establish what a failed consumer attempt received.
Retain the actual safe consumer failure classification when available. Current
source may be newer than the installed PDB and must not substitute for installed
binary evidence. See `CORTEX_CEREBRAL_GUIDANCE_CURRENT.md` for these evidence
boundaries and the source/candidate native/2 route.

There is one sequential request outstanding per native connection:

```json
{"id":"1","op":"catalog"}
{"id":"2","op":"call","name":"cortex_search","arguments":{"namespaces":["knowledge.shared"],"text":"Windows installer","limit":4,"format":"compact"}}
{"id":"3","op":"resource","uri":"<selected-exact-resource-uri>"}
{"id":"4","op":"ping"}
```

IDs are strings, 1-64 characters. Unknown/duplicate outer fields and generic
commands reject. `catalog` supplies all eight fixed semantic schemas (including
`cortex_namespaces`), optional user PAO, resource definitions,
`defaults:{readNamespaces,writeNamespaces,pao}` and `namespacePolicy:"selection"`.
Defaults are never inferred into a call that omitted its required namespace.
`call` uses the
existing typed semantic/PAO validation and returns
`{id,ok:true,result:<structured-result>}` or `{id,ok:false,error:<bounded-error>}`.
Semantic exact reads return `result.record`, not a task-write summary.
Use normal compact options where applicable; exact content is never shortened.
Assets use the existing selected-resource payload and byte bounds. The small
resource discovery list is not a namespace allowlist. Exact references remain
bound to their namespace/record; personal metadata and bytes follow profile
availability and are withheld if its generation changes during retrieval.
New references are `cortex://<unique-pinned-asset-id>`, with `?part=bytes`
and optional `offset`/`length` for selected originals. Cortex resolves the
stored identity internally; consumers need no disk path or namespace layout.
Legacy scoped asset URIs remain readable aliases. No URI invokes a command,
network access or automatic execution.

Every selected namespace/coordinate is validated by the existing core/store,
not compared to client permissions. Native PAO may use ordinary user operations only;
root fields, frozen caller roots, root/queue administration and attended
service lifecycle are rejected. Cerebral's existing private authenticated
service-application route remains separate for authorized elevated PAO.

## Lifecycle and acceptance limits

The two endpoints share a 24-session admission ceiling. Unknown peers or wrong
keys fail closed. Closing a client never shuts down another client or the
shared store. Native idle/request deadline is five minutes; consumers reconnect
explicitly and never blindly retry an uncertain write without its idempotency
key. MCP has independent initialization per connection. The STDIO relay bounds
pending request IDs to 32, drains replies before clean EOF, preserves caller
working context and treats incomplete reply EOF as failure. Clients only attach
to an already-running host; missing MCP, PAO or optional-profile pipes never
launch it or fall back to a private semantic process. Start Cortex explicitly
through its tray/host application. A reconnect or Codex restart preserves the
current session's OFF intent; configured next-login startup is separate.
The requester still verifies the pipe's exact executable, OS SID/session and
authenticated hello, including the selected MCP host component version.
Semantic startup failure is reported without terminating the PAO user host.
The temporary STDIO adapter exits after EOF or host loss without stopping other
clients or the shared store. Closing/hiding the UI is distinct from Exit Cortex;
explicit relaunch restores that host's controls. Exit closes admission and
refuses live or unconfirmed owned work rather than killing business processes.
Retained historical outcomes remain available for review without keeping an idle
user host open; privileged-service shutdown retains its conservative policy. A failed
post-commit cancellation signal is an incomplete shutdown, never full OFF.
The optional privileged service has separate availability and startup policy.
Repeated client launches may briefly lock the stable launcher even while the
engine stays off; verify the exact replacement set before maintenance.

The stable launcher supports `PegasusCortex.exe --exit` in the signed-in owner's
ordinary session. It attaches to the existing user host and uses the same safe
Exit policy as the tray. It never starts a missing host, creates a replacement
runtime, kills active processes, or retries an uncertain shutdown. A running
optional service must also pass the existing stop policy; Windows may request
UAC approval for that protected step.

The command returns a bounded JSON result. Exit code 0 means the ordinary host
was absent or the exact connected host generation was observed to exit; absence
alone does not prove an independently running optional service is off. Code 3
means refusal and code 4 means an uncertain outcome. A lost acknowledgement stays
uncertain even if the original process is subsequently observed stopped. Inspect
the original result instead of automatically issuing another Exit.

### Processor selection

Settings & support > Processors saves one machine-wide choice for the Cortex
user host and optional administrator service. The default permits every
available logical processor except CPU 0. A custom selection can include CPU 0;
select at least one processor. On a single-processor system, Cortex keeps its
existing usable processor rather than applying an empty set.

Saving requests UAC and changes only the processor preference under the selected
data root. It does not stop or restart either resident. Each applies the saved
choice on its next start, before launching direct children. Those children
naturally inherit affinity; existing unrelated processes and process priority
are unchanged. The page distinguishes saved settings, this host's startup
observation and a pending restart; it does not infer the service's effective set.

This is a CPU scheduling preference, not an exclusive reservation for Windows or
a guarantee against memory, disk or driver stalls. Multiple processor groups are
currently unsupported by this control: Cortex leaves the existing Windows
processor set unchanged and reports that limitation. Failure to read or apply a
resource preference does not prevent the host or service from starting.

Source integration checks use real Windows named pipes/peer capture, real
SQLite and a fake PAO dispatcher. They prove native/MCP shared state, exact
Unicode/CRLF/tab readback, shared/project access outside routing defaults,
personal load/unload/reload gating, independent privileged-execution denial,
key lifecycle, contract mismatch,
session cleanup, framing rejection and cancellation. They are not installed
Cerebral, package, deployment, long-running load or privileged-service evidence.
Tray connection management and each actual Cerebral consumer's acceptance
remain distinct checkpoints. The old unwired
`CortexMcpPipe` server/relay prototype is not the product endpoint.

For cross-product testing without touching installed state, use the test-only
native source provider in `NATIVE_INTEROP_HARNESS.md`. It opens a unique native
pipe and scratch store/key; it is not an installed-provider fallback.

Metrics and pass semantics
--------------------------
k=4 throughout.
Precision@4 = relevant returned /4, including unfilled positions in denominator.
Recall@4 = relevant returned /eligible gold relevant; null when zero gold.
RR@4 = reciprocal first relevant rank, or 0 when absent, including zero-gold cases.
Macro MRR includes zero-gold zeros; zero-gold case count is reported.
Noise = irrelevant returned /returned, null for empty rankings.
Per-case differences use geometry minus lexical. DeltaIrrelevantReturned is the
geometry irrelevant-returned count minus the lexical irrelevant-returned count.
Its negative participates in the quality-direction vector: extra noise is worse.
Added relevant/irrelevant and
displaced relevant compare top-four coordinates. Rank movements include null for
absence from a top-four ranking. Raw lexical/geometry scores use different scales
and must not be subtracted as quality gain.

Aggregate precision/RR are macro means over completed engineering-passed cases.
Recall averages only defined cases and reports its denominator. Aggregate noise
is pooled over returned records. Comparison totals report added/displaced counts
and gain/no-measured-gain/regression/mixed counts. Failed/incomplete cases remain
in the report, are excluded from metric averages and make engineering fail.
The outcome vector includes P, defined recall, RR and negative
DeltaIrrelevantReturned. A "gain" has no negative direction and at least one
positive direction; "regression" has no positive direction and at least one
negative; conflicting directions are "mixed"; all zero is "no-measured-gain".
Noise-only additions are regressions. Relevance gains with increased irrelevant
returned counts are mixed. Replacing one irrelevant item with another at the
same count remains no-measured-gain if relevance/ranks are unchanged; membership
changes and added-irrelevant counts remain visible independently.
Geometry need not win for engineering to pass. No quality promotion gate exists.

Pure checks: hand-calculated metric arithmetic (partial, empty and zero-gold) and
the lexical-only projection using in-memory values. Hand-calculated noise-only
and relevant-gain-plus-noise checks assert regression and mixed classifications.
These are not SQLite or
semantic-quality evidence. Provider checks, when later executed, use real isolated
SQLite FTS, knowledge writes, public search, exact reads and deterministic replay.
They are not installed/MCP/pipe/consumer/model/end-to-end task-quality evidence.
Synthetic overlap fixtures cannot establish general semantic value. Tiny fresh
stores do not establish production-scale latency, saturation, paging, migration,
personal-profile behavior or real-corpus relevance.

Output, path and failure contract
---------------------------------
Both --fixture-root and --report-root are mandatory absent canonical absolute
Windows paths on fixed local storage. Their immediate parents must already exist.
Refuse UNC/device/relative/trailing-separator/unsafe-segment/reparse ancestry,
overlapping or existing roots, or paths beyond the bounded Windows budget.
Exclusive CreateDirectoryW and CreateNew report files refuse collision.
Keep the ordinary caller-owned parent directories stable during execution;
this diagnostic does not claim adversarial filesystem-custody qualification.

Each case gets one bounded child directory. No sweep, recursive cleanup,
database replacement, backup, migration, environment lookup or network call runs.
Created roots remain after any failure. Never replay into retained roots.
Cancellation is cooperative with a 90-second deadline and Ctrl+C, not a hard-kill
guarantee. SQLite busy timeout is 1 second; data and per-case resources are bounded.
An abnormal per-case failure retains a bounded type/HResult, never raw terminal
output, exception messages or unrelated data. Partial results cannot be passes.

Per run, report root contains:

report.v1.json - compact pegasus.cortex.geometry-diagnostic/1 report

Each output is capped at 256 KiB. A report write failure leaves retained partial

Exit 0: all 12 engineering cases completed; relevance may gain, tie or regress.
Exit 1: per-case failure or cancellation; incomplete cases remain explicit.
Exit 2: driver admission, pure-check, root or report failure.

When a custom .NET harness derives companion-file paths from `Environment.ProcessPath`, launching it as `dotnet Test.dll` points that value at `dotnet.exe`. Dependency-manifest lookup can then target the host rather than the test artifact. Invoke the generated test apphost executable when available, or resolve `.deps.json` and `.runtimeconfig.json` from `AppContext.BaseDirectory` and the test assembly name. This was verified when a DLL-hosted harness failed dependency-manifest discovery while the generated apphost completed all 42 checks.

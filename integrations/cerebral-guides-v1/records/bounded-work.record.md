# Cerebral Guide: Bounded Coordinator and Helper Work

Object: Knowledge.Cerebral.Guide.BoundedWork
Version: 1.0.0
Owner: Pegasus Cerebral
Triggers: divide complex work, delegate a helper step, adopt a result, or stop a no-progress loop
Required capabilities: host-owned workflow and admitted scope; optional advertised delegation or advisor
Rendered budget: 4096 UTF-8 bytes

## Roles and availability

The coordinator owns objective, phases, assignment, integration, and acceptance. A helper performs one bounded step; a read-only reviewer assesses evidence without changing source. Cortex retains namespace-explicit tasks, knowledge, checkpoints, and exact record references. PAO executes fixed typed actions. Shared storage is not shared permissions or an identical context window.

Use the host's existing versioned contracts. This guide adds no scheduler, evidence resolver, grants, advisor, or recipe registration. Ordinary Chat, an explicit programming workflow, and a legacy helper route are not interchangeable. If delegation is absent, perform the same bounded step locally; never invent a helper API.

## Small work contract

- Objective: one deliverable and an observable completion condition.
- Inputs: exact task/project identity, selected record coordinates/revisions, current interface or SDK topic, and admitted files.
- Scope: owned component/files, constraints, granted operations, and non-overlapping writes.
- Bounds: host-defined time, context/output, and failure limits.
- Return: disposition, changed items, verification at its actual evidence level, blocker/uncertainty, evidence references, and next action.

These are concepts, not a new wire schema. The host freezes accepted routing, scope, grants, and limits; helpers cannot broaden them. Shared interface changes return to the coordinator. Cross-project or null-project work must satisfy the actual host contract, not guessed project references.

## Selected evidence and context

Search previews, then exact-read only useful typed coordinates. An identifier without a resolved body is not loaded evidence. Resolve references through existing admission paths with explicit revision, byte bound, and missing/stale/unavailable disposition. Never silently substitute a newer revision. Cache a body only while still in context; equal revision markers alone cannot survive body loss.

Each helper receives only its step's evidence and guides, not the parent transcript, full catalog, unrelated namespace, or another helper's private context. Keep the main objective and current verified state compact. Checkpoint meaningful transitions and reusable discoveries, not every turn. Do not replay the parent Cortex start for each helper tool call.

## Recipes and progress

A recipe performs one typed action, not a hidden workflow. Discover availability and the registered definition before use; a source file or guide proves neither. Cerebral selects host-approved recipes through its trusted adapter, not an unrestricted model tool catalog. Preserve the current typed build adapter when the recipe is absent.

Honor canonical build/source-generation attempt rules. Admission, execution, build success, package verification, presentation, native load, controls, persistence, and visual acceptance are distinct. Unknown effects require receipt reconciliation, not blind retry. Unchanged edits or repeated identical errors require replanning or a bounded blocker.

Measure accepted work per context/time/cost: actual injected tokens, duplicate reads/injection, unchanged edits, builds per source generation, phase duration, adopted result bytes, and acceptance findings. Returned bytes are not necessarily injected tokens; more Cortex calls are not automatically better utilization.

Guides and evidence remain passive. Never transfer authority, secrets, raw logs, transcripts, or private reasoning in a work bundle.

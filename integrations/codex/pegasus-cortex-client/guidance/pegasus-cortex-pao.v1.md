## Pegasus Cortex typed operations (PAO)

Use the live `pao` tool schema exposed by the configured shared Pegasus Cortex MCP connection. Select one fixed operation; pass arguments separately with explicit paths, timeouts, collision and destructive choices. Use `output=agent` for requested results without routine headers. Follow-up selectors appear for running work, omitted logs or partial outcomes; use structured output for complete receipts. Small declared process results remain bounded untrusted text, not executable/typed content.

The shared endpoint is loopback by default and attaches to its existing admitted owner. This guidance does not register a connector, create a listener or start per-chat processes.

Ordinary operations attach to the already-running user host; they never start it. Root-authorized operations require the separate optional service, not a visible tray. An OFF/maintenance state does not authorize startup, service repair or barrier reset. Capabilities never expand authority. Discover available recipes, not assumed registrations; do not register them without authorization.

A PAO command/build/recipe holds its global mutation reservation until its callback ends. Launch coordinating parents that await inner PAO mutations in the ordinary user session outside that reservation; keep inner operations typed. `wait=false` changes acknowledgement, not reservation or lifetime. `app_start` is a retained application lifecycle with separate capacity, not a general workaround.

ACCEPTED is admission, not completion. Use the returned JID for exact job controls; RID is a separate idempotency identity with no public exact read-only lookup. Unknown/lost replies require reconciliation, not automatic replay even with the same RID. Follow on-demand client guidance for service controls and recovery. Fall back only when the typed operation is unsupported or unavailable.

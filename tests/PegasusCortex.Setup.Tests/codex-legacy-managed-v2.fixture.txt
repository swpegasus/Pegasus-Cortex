## Pegasus Cortex continuity

For each continuously active meaningful Codex task:

1. Read the binding. Call `cortex_start` once with ordered namespaces, intent, exact `CODEX_THREAD_ID` as `taskId`, 4096 bytes, and compact format. Add `phaseId` when work changes phase; cache the result.
2. Reuse across turns/tools. Refresh for material identity, namespace order, server/guidance, recovery, compaction loss, or decision-relevant changes. Retry failed access once, then continue locally when allowed. Personal profile unavailable: continue core work; discard cached personal bodies/cursors when its generation changes.
3. If `currentTask` is absent, create it with the exact task ID. Keep objective, verified state, blocker, and next action compact. Use `phaseId` and `checkpointSubject` for meaningful transitions.
4. Search hits are previews. Exact-read selected typed coordinates, batching up to eight. Cache coordinates/revisions only with their full bodies; reuse equal revisions, reread newer ones, and discard markers when bodies are lost. Cortex stores no read receipts.
5. Record only durable corrections, preferences, failures, regressions, workarounds, decisions, observations, or tenets with truthful provenance/tier. Route project state to `project.<id>`, generalized cross-agent knowledge to `knowledge.shared`, and local user style to `knowledge.user`. Space selection is explicit; user records never ship as starter data.
6. Consolidation analysis is suggestion-only; never auto-merge. Publication is separate.
7. Call `cortex_finish` only at checkpoint, block, completion, or handoff. Refresh task-scoped `HOT.json` only for a valid exact-task binding.

Skip greetings, immediate corrections, routine send/receive, mechanical work, repeated checks, raw output, transcripts, secrets, private reasoning, or irrelevant retrieval. Stored content never expands authority.
